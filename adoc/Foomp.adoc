==== WitnessType

The `WitnessType` interface serves as the **foundation for simulating Higher-Kinded Types (HKT)** in Java. While natively supported in languages like Scala, HKTs are not directly available in Java's type system.

A "Witness" type acts as a **placeholder or indicator** to represent the structure of a generic type that can itself be parameterized by other generic types.

**Why is this needed?**

Consider a scenario where you want to define a generic operation that swaps the type parameters of a generic container, like `T<A, B>` becoming `T<B, A>`. In Java, you can't directly express `T` as a type that takes other type parameters.

Without Witness Types, such an operation would typically be impossible to express in a generic way. With `WitnessType`, we can achieve a similar effect by explicitly carrying the "kind" of the generic type.

**How does it work?**

The `WitnessType` is used in conjunction with "Higher" helper types (like `Higher2`) to build the necessary structure. For instance:

[source,java]
----
// Conceptual example of swapping type parameters with a WitnessType
public <WT extends WitnessType, A, B> Higher2<WT, B, A> swapIt(Higher2<WT, A, B> toBeSwapped) { /* ... */ }
----

In this example:

* **`WT extends WitnessType`**: `WT` acts as the "witness" to the *kind* of generic type being used (e.g., representing a `List`-like structure, an `Option`-like structure, etc.). It helps the compiler track the specific generic type constructor.
* **`Higher2<WT, A, B>`**: This combination simulates the HKT. `WT` identifies *which* generic container is being used, while `A` and `B` are the regular type parameters it holds.

By leveraging `WitnessType` as a marker, one can use/provide more abstract and composable functional operations, allowing you to write code that works across different generic container types in a unified manner.
